CORE THESIS

AI 写的代码为什么总是"差一点"？

不是模型不够强。是没有领域知识、没有质量收敛、没有独立审查。
Pipeline 10/10 信心的代码，100% 功能失效 — 发生过 (C011)。

结构性保证 > 概率性祈祷

DESIGN PHILOSOPHY

七个设计哲学

01

证据 > 断言

"我实现了" 不算。test_x passes 才算。无外部证据 = 未完成。

02

二元门禁，没有灰度

PUSH-READY 或 NOT-PUSH-READY。没有 7/10 够了。All-or-nothing。

03

4+1 专家独立审查

Correctness · Security · Performance · API Contract + 条件触发 Red Team。
不是 1 个通才走过场。每个专家有独立上下文和专用 checklist。

04

TDD 垂直穿透

一个测试 → 一段实现 → 提交。每个 cycle 回应上一个学到的。永远不横着切。

05

6 层质量收敛

Tests · Types · Regressions · Adversarial · DDD · Decisions — 全部同时通过。5/6 ≠ 可交付。

06

DDD 学习闭环

EVALUATE 读 IMPROVEMENT.md（学习过去）→ REFLECT 写 IMPROVEMENT.md（教育未来）。每次 run 更强。

07

执行前定义退出条件

每个阶段先声明：什么算成功 (SIGNAL)？什么算失败 (FAIL)？怎么验证 (CHECK)？
防止 "感觉差不多了" 的 vibes-based pass。

ARCHITECTURE DECISIONS

设计决策 — 犯过的错才知道的事

每条规则背后都有一个 COE。不是最佳实践，是血泪教训。

A1 — SINGLE AGENT

单 Agent 切换角色 > 多 Agent 编排

上下文传递成本 = 0。分工是人类认知带宽的妥协，不是最优设计。

A2 — SUB-AGENT RULE

只在 Review 时 spawn 子 Agent

Builder 需要连续性（上下文）。Reviewer 需要无偏见（无上下文）。用途决定架构。

A3 — TDD DISCIPLINE

改代码，永远不改测试

测试 = 需求规格。测试失败 = 代码有 bug。改测试 = 偷偷改了需求。

A4 — CULTURE AS CODE

970 行指令 = 可执行的工程文化

不是文档。是 Agent 的行为约束。每条规则背后有一个真实 incident。

A5 — CHECKPOINT > COMPRESS

暂停 > 压缩

预算紧？Checkpoint。不跳阶段、不简化 review、不"差不多就行"。质量无折扣。

A6 — SDD PRINCIPLE

PLAN 做难思考，BUILD 做简单执行

File discovery + Change spec + Test strategy 都在 PLAN。BUILD 只是按顺序写代码。
