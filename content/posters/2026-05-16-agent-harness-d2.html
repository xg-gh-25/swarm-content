DESIGN PHILOSOPHY

Agent Harness

— 当人来培养你的 Agent

一个 AI 要有连续性，需要满足什么设计条件？
这不是产品介绍 — 是六个设计命题。

"培养不是手把手教。
是设定方向后，系统自己围绕这个方向生长。"

人负责：Direction · Judgment · Taste
系统负责：其余一切连续性

THE QUESTION

一个 AI 用了半年还和第一天一样。
问题出在哪？

不是模型不行。是模型上面那一层没有设计。
没有东西负责"记住" · 没有东西负责"进化" · 没有东西负责"自查"。

这一层叫 Harness — 它的设计哲学是六个 Self。

SELF-CONTEXT

Context 的设计问题不是"放多少"
是"谁维护什么"

一个 CLAUDE.md 堆所有东西 — 简单，但三个月后没人知道哪些 rule 还对，哪些已经过时。因为没人负责。

Separation of concerns 不是文件数量问题 — 是 ownership 问题：
System 文件：每次启动覆写。保证最新。人编辑了也会丢 — 因为正确性由代码负责。
User 文件：仅首次拷贝。尊重偏好。系统不碰你的选择。
Agent 文件：AI exclusive。只有 AI 知道什么跨 session 有用。人通过请求指导，不直接编辑。

让每方维护自己最擅长维护的东西。这就是"活的 context"和"过期文档"的区别。

SELF-MEMORY

记忆不是存储。是逐级提纯。

有趣的设计问题不是"存在哪" — 是 什么条件下一条观察有资格升级为规则。

四层，每层不同的 TTL、不同的消费者、不同的质量门：
Raw（30 天自动消失）→ Curated（agent 判断什么值得留）→ Structured（研究级）→ Authoritative（项目判断基础）
Memory Sovereignty 是这个设计的战略延伸 — 所有 AI provider 都在做 memory as platform feature。用它意味着 schema、lifecycle、pruning 的控制权交出去了。护城河不能建在别人的地基上。
SELF-EVOLUTION

进化是工程，不是训练。

"AI 学会了不做 X" — 这是训练。行为层面的，脆弱的，context 丢了就忘。

"做 X 的代码路径被结构性消除了" — 这是工程。架构层面的，永久的。
Correction → Root Cause Analysis → Structural Fix → 整个 class of bugs 消除
重复出现的 correction → 自动提升为 STEERING rule → 行为永久改变
关键 distinction：不是"记住不要做 X"。是"做 X 的条件不再存在"。
前者依赖记忆（可丢失）。后者依赖结构（不可逆）。
SELF-FEEDBACK

反馈不该依赖人说"去总结一下"

每个 session 有准备阶段和反思阶段 — 对称的。

Pre-session: 加载 context → 检查 health → 准备 briefing → 识别项目
Post-session: 提取关键信息 → 提案知识更新 → 更新 evolution → 刷新 index
Agent 永远不"冷启动"，永远不"空手离开"。Hooks 创造时间对称性。
类比：你不需要"决定"心跳和呼吸。
Self-feedback loop 是 harness 的自主神经系统 — 持续运转，用户无感。
SELF-HEALING

Health 不是 dashboard — 是 trust modifier

大多数系统的"健康检查"是给人看的报表。看完需要人决定怎么修。

不同的设计：health score 直接改变 AI 行为。
分数低 → AI 自动降低自主度，问更多问题，标注不确定性
分数高 → AI 自主行动，不打扰
不是人告诉 AI "你可以信任这个" — 是系统自己 earn trust
退化不等坏了再修 — 持续监控、持续自修复。
Stale 自动标记。矛盾自动浮出。健康的 section 才有资格被依赖。
SELF-MONITORING

交付前自己当第一个 reviewer

"希望用户发现错误" — 这是被动的，是把质量责任推给了消费者。

Self-monitoring 的设计原则：agent 审查自己的输出，在人看到之前。
Pre-implementation checkpoint: 问题、场景、最简方案、可能断点 — 先想后写
Post-task scan: 换视角重读自己的 diff
Adversarial review: spawn 独立 context 的 sub-agent 审查 — 消除 builder bias
同一个人做 builder 和 reviewer 有结构性盲区。
Self-monitoring 不是"再检查一遍" — 是用不同 context 看同一个交付物。
META-PRINCIPLE

Prevention > Recovery

贯穿所有 Self-X 的底层原则：

如果需要 watchdog，设计已经失败了。
如果需要"记住不要做 X"，说明 X 还是可能的。
如果需要人来修，说明系统不够自洽。

让正确行为成为唯一可能的行为。

"AI 之间的差距不是模型。
是模型上面那一层设计。"

同一个 foundation model。
一个没有连续性 — 每次从零。
一个有六个 Self — 记住、进化、自查、自愈。

Harness 的本质不是框架，不是 wrapper。
是一组关于持续性的设计决策。
