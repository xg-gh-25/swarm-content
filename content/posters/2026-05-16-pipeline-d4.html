为什么 AI 写的代码
总是"差一点"？

不是模型不够强。是没有领域知识、没有质量收敛、没有独立审查。

Coding as Black Box = 结构性保证，不是概率性祈祷。

// DESIGN_PHILOSOPHY [7]

七个设计哲学

01

DDD 驱动判断

每个阶段读领域文档。过去的失败 → 未来的门禁。
EVALUATE 读 IMPROVEMENT.md；REFLECT 写 IMPROVEMENT.md。闭环。

02

TDD: 垂直穿透，非水平切片

一个测试 → 一段实现 → 提交。不是"先写所有测试再写所有代码"。
每个测试回应上一个 cycle 学到的东西。

03

6 层质量收敛

Tests · Type-safe · No Regressions · Adversarial Clean · DDD Conformance · Decisions Resolved
全部同时通过 = Push-Ready。5/6 ≠ 可交付。迭代直到收敛。

04

Adversarial Review: 结构性第二视角

全新上下文的子 Agent 独立审查。零 builder 偏见。
发现了 16 轮自检漏掉的 zombie state bug。非可选。

05

证据 > 断言

"我实现了 X" 不是证据。`test_x passes` 才是。
"我审查了代码" 不是证据。"3 findings, all fixed" 才是。

06

二元推送门禁

没有分数，没有 "7/10 够了"。
PUSH-READY 或 NOT-PUSH-READY。All-or-nothing。

07

每个阶段必经 — 这是学习闭环

跳过 REFLECT = 打断学习。跳过 EVALUATE = 重复已失败的路径。
每个阶段有目的，跳一个 = 未来更多工作。
