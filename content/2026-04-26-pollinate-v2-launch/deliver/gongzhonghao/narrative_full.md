# 一句话进去，5个平台的内容出来

上周六下午，我打了一句话：

> "做一个关于 AI Pipeline 如何自主交付代码的视频"

3小时后我收到了：一个4.5分钟的4K视频、65条字幕、3种尺寸的封面、一个66秒的竖版精选Shorts、5个平台的发布文案。

这不是demo。这是我每天在用的工具。

它叫 **Pollinate**，是 Swarm 的媒体价值交付引擎。今天聊聊我为什么要造它，以及它怎么工作的。

---

## 问题：从"想说"到"发布"有20步

技术人不缺知识。你在公司里解决了一个难题，写了一个框架，踩了一个大坑——这些都是极好的内容素材。但做成内容？

1. 写脚本
2. 配音（或找TTS）
3. 做视觉（图表、动画、排版）
4. 做封面（16:9 播放页 + 4:3 推荐流 + 3:4 小红书……）
5. 加字幕
6. 加BGM
7. 渲染
8. 写B站标题/描述/标签
9. 写YouTube标题/描述/标签（英文）
10. 写小红书文案（种草风，200-500字，emoji）
11. 写抖音文案（短平快）
12. 做竖版裁切（9:16）
13. 检查各平台规格（分辨率、码率、时长）
14. 上传×5
15. ……

20步。每一步都不难，但串起来就是一个下午。大多数人的知识永远停留在脑子里。

**这不是创意问题。这是工程问题。**

当每一步都有明确的输入、输出和质量门控时，AI可以端到端驱动整条链路。

---

## 解法：9阶段闭环 Pipeline

Pollinate 不是一个"AI写脚本"的工具。它是一条完整的媒体价值交付流水线：

```
INTAKE → EVALUATE → STRATEGIZE → PLAN → BUILD → REVIEW → TEST → DELIVER → REFLECT
                        ↑ 关键                                     ↑ 关键
```

两个关键阶段值得展开说：

### STRATEGIZE：不是你选格式，是AI选格式

v1 的 Pollinate 是 "video-first"——你说做视频，它就做视频。但同一个 message，在不同平台的最优格式是不一样的：

| 渠道 | 用户行为 | 最优格式 |
|------|----------|----------|
| 小红书 | 刷图文，3秒决定停不停 | 海报 + 种草短文 |
| B站 | 看深度内容 | 长视频 + 动态长文 |
| 公众号 | 读长文，转发给同事 | 叙事长文 |
| 抖音 | 15秒内划走 | 竖版Shorts |
| GitHub | 看代码 | README |

所以 STRATEGIZE 阶段做的事情是：**先写 PR/FAQ（定义价值），再生成渠道×格式矩阵（每个渠道的最优格式）**。Pipeline 自主决策，只在判断型决策时问你。

### REFLECT：同一辆车只翻一次

Pipeline 有19个质量检查项（Review Pattern），**每一个都从真实翻车中来**。

举个例子：第一个用 Pollinate 做的视频，Pipeline 给自己打了10分满分。交付后我试了一下——功能100%不能用。原因：Content-Type 写错了一个字段。14个测试没一个真正发过HTTP请求。

翻车后加了3个检查项。下次不会翻同一辆车。

REFLECT 阶段做的事：记录每次翻车，变成检查项，结构性地防止复发。Pipeline 自我进化。

## 真实案例：这篇文章本身

你正在看的这篇文章，就是 Pollinate v2 的一次运行产出。

输入：`"Pollinate v2 推广 — 让AI实践者知道这个工具存在"`

Pipeline 自主决策的渠道×格式矩阵：
- **小红书**（P0）→ 海报 + 种草短文
- **B站**（P0）→ 海报 + 动态长文
- **公众号**（P1）→ 你正在读的这篇叙事长文
- **GitHub**（P1）→ README 更新
- **抖音/视频号** → 跳过（受众匹配度不够，等有demo视频再做）

一次输入，多条 track 并行生产，按渠道打包交付。

## 架构（给技术人看的）

```
Message (用户输入)
    │
    ▼
┌─────────┐     ┌──────────┐     ┌────────────┐
│  INTAKE  │────▶│ EVALUATE │────▶│ STRATEGIZE │
└─────────┘     └──────────┘     └────────────┘
                                       │
                              PR/FAQ + Channel Matrix
                                       │
                              ┌────────┴────────┐
                              ▼                  ▼
                        ┌──────────┐       ┌──────────┐
                        │  PLAN    │       │  PLAN    │
                        │ (video)  │       │(narrative)│
                        └────┬─────┘       └────┬─────┘
                             ▼                  ▼
                        ┌──────────┐       ┌──────────┐
                        │  BUILD   │       │  BUILD   │
                        │  (TTS,   │       │ (write,  │
                        │ Remotion,│       │ humanize)│
                        │ 4K, BGM) │       │          │
                        └────┬─────┘       └────┬─────┘
                             ▼                  ▼
                        ┌──────────────────────────┐
                        │    REVIEW (per-format)    │
                        │  RP-V (video) │ RP-N (nar)│
                        └──────────┬───────────────┘
                                   ▼
                        ┌──────────────────┐
                        │     DELIVER      │
                        │  小红书 │ B站 │ 公众号 │ GitHub
                        └──────────┬───────┘
                                   ▼
                        ┌──────────────────┐
                        │     REFLECT      │
                        │ 经验 → 检查项进化  │
                        └──────────────────┘
```

核心设计原则：
- **PR/FAQ 是唯一源文档** — 所有格式都是 PR/FAQ 的不同维度投影
- **格式跟着受众走** — 不是先选格式再想内容
- **Parallel tracks** — video、narrative、poster 并行生产
- **Per-channel deliver** — 每个渠道拿到的是 publish-ready 的完整包

## 技术栈

| 组件 | 技术 | 为什么选它 |
|------|------|-----------|
| TTS | Amazon Polly (Zhiyu/neural) | 和 Swarm 语音对话同一个声音，SSML 增强 |
| 视频渲染 | Remotion (React) | 代码即视频，组件化，4K 原生 |
| 竖版裁切 | generate_shorts.py | 原生重新渲染，不是裁切 |
| BGM | FFmpeg mix | 自动循环+淡入淡出 |
| 质量检查 | check_specs.py + 19 RP-V | ffprobe 验证 + 品牌一致性 |
| 渠道配置 | YAML (pollinate-accounts.yaml) | 5平台账号，一处配置 |
| 话题积压 | topic_backlog.py | Signal digest 自动发现话题 |
